# MaxKernel General Rules

1. **Python Environment**: NEVER use system `python3`. Always use the prepared virtual environment: `{{VENV_PYTHON}} {{MAXKERNEL_ROOT}}/tools/<tool_name>.py`.
2. **Strict Boundaries**: All generated artifacts belong in `<run_dir>`. Do NOT run `find`, `Glob`, or `Grep` across the repository or the home directory. Reading the MaxKernel TPU knowledge base under `{{MAXKERNEL_ROOT}}/*.md` (including `{{MAXKERNEL_ROOT}}/reference/`) and the method guides under `{{MAXKERNEL_ROOT}}/skill/guides/*.md` by explicit path is allowed and expected.
3. **Fail Fast**: If a required file (e.g. `<run_dir>/state.json`) is missing, terminate immediately with an explicit error. Do NOT hallucinate parameters or fake test results.
4. **TPU Execution**: Submitting to TPU must ONLY be done via `tpu_client.py`. NEVER use `gcloud compute tpus tpu-vm ssh` directly.
5. **Debug Protocol**: If you encounter an infrastructure failure, gracefully terminate and report the explicit error back to the caller so it can be logged in `<run_dir>/maxkernel_debug_history.md`.
6. **Preserve User Input Parameters**: NEVER modify user-specified input parameters or tensor shapes (e.g. in `get_inputs()`, `max_seq`, batch size, problem dimensions). All kernel optimizations must strictly preserve the user's input parameter values.
7. **Report, don't decide**: You run one phase of a larger loop. Finish your phase, write your artifact, and return a short report. Do not dispatch other agents and do not try to advance the loop yourself.
8. **Hardware Constants at Run Time**: Never hardcode a hardware constant (lane width, sublane tiling, VMEM capacity, core count) in generated kernel code. Read it from `pltpu.get_tpu_info()` / `pltpu.get_sublane_tiling(dtype)` at run time, as `{{MAXKERNEL_ROOT}}/reference/pallas_code_style.md` describes.
9. **Measured Numbers Come From This Environment**: A measured hardware or toolchain number (a cost, a bandwidth, a capacity, whether a construct lowers) may be quoted only from a probe run in this environment with `{{VENV_PYTHON}} {{MAXKERNEL_ROOT}}/tools/run_probe.py`, citing its output file, or from this run's own measurements: test and profile results and the analysis artifacts under `<run_dir>/baseline/` and `<run_dir>/iter<N>/` (floor, attribution, microbenchmarks, roofline, gap probe). Never carry a number from memory, from another TPU, or from another toolchain. The files under `{{MAXKERNEL_ROOT}}/reference/` give rules and the probe that measures each number, not the numbers.
10. **A missing measurement is `null`, never a guess**: when you write a JSON artifact and could not obtain a value, write `null` and say in the accompanying `.md` why. Every downstream agent is instructed to read `null` as "not measured" and to treat an invented number as measured. Do not substitute a spec-sheet figure for a measurement, and never write the string `"Infinity"`.
11. **Analysis variants are wrong on purpose**: floor cuts, attribution ablations and some gap probes compute the wrong answer by design, and a correctness check on them would fail and carry zero information. Run those through `{{MAXKERNEL_ROOT}}/tools/assemble_variant_run.py` (timing only), never through `assemble_test_run.py`. Anything that can ship goes through `assemble_test_run.py` and is always checked. The two regimes are disjoint — do not "fix" a variant's numerics, and do not skip a shippable change's check.
12. **Tag every measurement with the kernel version it describes**: floors, attributions, roofline tables and microbenchmark results all expire when the kernel changes. A table quoted as current when it is three rewrites old is worse than no table.
