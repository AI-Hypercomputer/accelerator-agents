# jax_perf/splash_attention_debug — Splash vs flash attention mask-mode benchmark

<!-- connect:up:begin -->
> **Cross-repo concept:** part of [flash-attention](../../../concepts/flash-attention.md), [splash-attention](../../../concepts/splash-attention.md) across this wiki's repos.
<!-- connect:up:end -->
A Flax wrapper ([`SplashAttention`](../catalog/jax_perf/splash_attention_debug.md#SplashAttention)) around JAX's Pallas TPU splash-attention kernel (`jax.experimental.pallas.ops.tpu.splash_attention`), plus a benchmark ([`main`](../catalog/jax_perf/splash_attention_debug.md#main)) that measures the same Q/K/V under four attention strategies — dynamic mask, static mask, static causal mask, and the plain (non-splash) flash-attention kernel — to quantify the cost of mask *dynamism* versus mask *shape* on TPU.

## Entry points
- [`SplashAttention.__call__`](../catalog/jax_perf/splash_attention_debug.md#SplashAttention.__call__) — the Flax module's forward; every attention call in the benchmark goes through here, which wraps the actual kernel invocation in `shard_map` over [`mesh`](../catalog/jax_perf/splash_attention_debug.md#SplashAttention.mesh).
- [`main`](../catalog/jax_perf/splash_attention_debug.md#main) — builds a trivial `(1,1,1,1)` mesh, constructs one `SplashAttention` module, generates `(batch=4, heads=16, seq=8192, head_dim=128)` Q/K/V, and times each of the four strategies for 3 iterations apiece.

## Mechanism (step-by-step)
1. [`SplashAttention.__call__`](../catalog/jax_perf/splash_attention_debug.md#SplashAttention.__call__) builds a `q_segment_ids` default when only `kv_segment_ids` is given, then wraps [`splash_attention_helper`](../catalog/jax_perf/splash_attention_debug.md#SplashAttention.splash_attention_helper) in `jax.vmap` (via the closure [`static_helper`](../catalog/jax_perf/splash_attention_debug.md#SplashAttention.static_helper), whose comment notes it exists specifically "to ensure self is not overridden by shard_map accidentally") and then in `shard_map`, with `in_specs`/`out_specs` all derived from [`_qkvo_partition_spec`](../catalog/jax_perf/splash_attention_debug.md#SplashAttention._qkvo_partition_spec) and [`_segment_ids_spec`](../catalog/jax_perf/splash_attention_debug.md#SplashAttention._segment_ids_spec) — the vmap handles the per-head dimension (the splash kernel itself is invoked once per head, not batched over heads internally) while `shard_map` handles device sharding.
2. [`splash_attention_helper`](../catalog/jax_perf/splash_attention_debug.md#SplashAttention.splash_attention_helper) resolves segment ids into a `SegmentIds` pair, builds the mask via [`create_mask`](../catalog/jax_perf/splash_attention_debug.md#SplashAttention.create_mask), broadcasts it across heads into a `MultiHeadMask` (or repeats a raw dynamic-mask array), resolves block sizes via [`create_kernel_blocks`](../catalog/jax_perf/splash_attention_debug.md#SplashAttention.create_kernel_blocks) if none were passed, constructs the kernel with `splash_attention_kernel.make_splash_mha(mask=..., head_shards=1, q_seq_shards=1, block_sizes=..., attn_logits_soft_cap=None)`, and calls it on `query * scale_factor` — the query is pre-scaled by [`_calculate_scale_factor`](../catalog/jax_perf/splash_attention_debug.md#SplashAttention._calculate_scale_factor) (`1/sqrt(head_dim)`) *before* the kernel call because, per the inline comment, "splash attention does not support scaling" internally.
3. [`create_mask`](../catalog/jax_perf/splash_attention_debug.md#SplashAttention.create_mask) branches three ways: if `dynamic_mask` (a real `jax.Array`, e.g. a per-example timestep-derived boolean mask) is provided, it's used directly (and is incompatible with windowed attention — raises `NotImplementedError` if both are set); otherwise a `FullMask` is built and optionally intersected (`&=`) with a `LocalMask` (windowed attention) and/or a `NumpyMask` wrapping a caller-supplied static boolean array — the distinction between "dynamic" (a traced JAX array, re-evaluated and potentially re-lowered per call) and "static" (a Python-level `Mask` object baked into the kernel's specialization) is the central axis this file's benchmark measures.
4. [`create_kernel_blocks`](../catalog/jax_perf/splash_attention_debug.md#SplashAttention.create_kernel_blocks) derives `block_q`/`block_kv` from a `sequence_block_factor`-adjusted `512 * dtype_block_factor / seq_factor` formula, sets forward and dK/dV backward blocks to the same computed size, and sets the dQ backward blocks to `None` when `fuse_if_possible` (the default) — signaling the splash kernel to use its fused backward kernel path (`use_fused_bwd_kernel=True`) rather than a separate dQ pass; it also picks `QKVLayout.SEQ_MINOR` vs `HEAD_DIM_MINOR` based on whether the mesh actually shards the sequence dimension (`seq_factor == 1` or not).
5. [`main`](../catalog/jax_perf/splash_attention_debug.md#main) runs the same `(q, k, v)` through: (a) `splash.apply(..., dynamic_mask=...)` inside a plain `jax.jit(splash.apply)` — the mask array is a regular jitted argument, so it participates in tracing every call; (b) [`static_apply`](../catalog/jax_perf/splash_attention_debug.md#main.static_apply) — a separately-`jax.jit`-ted closure that hardcodes `static_mask` as a captured Python value (a NumPy array), so the mask is baked into the trace rather than passed as a traced argument; (c) [`static_apply_causal`](../catalog/jax_perf/splash_attention_debug.md#main.static_apply_causal) — identical, but the static mask is a [`CausalMask`](../catalog/jax_perf/splash_attention_debug.md#CausalMask) object (a lazily-computed structured mask) instead of a materialized NumPy boolean array; (d) [`flash`](../catalog/jax_perf/splash_attention_debug.md#main.flash) — the plain (non-splash) Pallas flash-attention kernel from `jax.experimental.pallas.ops.tpu.flash_attention`, with `causal=True` and hand-picked `BlockSizes`, as the non-sparse baseline.

## Key data structures
- [`CausalMask`](../catalog/jax_perf/splash_attention_debug.md#CausalMask) — subclasses `splash_attention_mask._ComputableMask`; its docstring describes a standard causal mask with a configurable `offset`, but the actual `causal_mask_function` implemented in `__init__` is `q_ids // 3 >= kv_ids // 3` — a block-of-3 grouped causal test, not the commented-out standard `q_ids >= kv_ids` (or `q_ids + offset >= kv_ids`) — evidence this file is mid-experiment/debug rather than a finished causal-mask implementation.
- `_flatten_mask`/`_unflatten_mask`, registered via `register_pytree_node(CausalMask, ...)` — both bodies are a bare `breakpoint()` followed by unreachable code, meaning `CausalMask` cannot actually be flattened/unflattened as a pytree without a debugger attached; this is dead/broken pytree-registration code left in place, not a working serialization path.
- [`SplashAttention.dtype_block_factor`](../catalog/jax_perf/splash_attention_debug.md#SplashAttention.dtype_block_factor) — computed as `jnp.ones(1, dtype=self.dtype).itemsize // 2` (i.e. half the byte-width of [`dtype`](../catalog/jax_perf/splash_attention_debug.md#SplashAttention.dtype), which is hardcoded to `bfloat16`) — a dtype-dependent scaling factor folded into the block-size formula in [`create_kernel_blocks`](../catalog/jax_perf/splash_attention_debug.md#SplashAttention.create_kernel_blocks).

## Dynamics (design intent)
> [!inferred] The file's own header comment records a prior run's measured wall-clock results on a v6e-8 (quoted verbatim from source): `dynamic` iterations at `3.42s, 0.059s, 0.059s`; `static` at `3.30s, 0.027s, 0.027s`; `static causal` at `0.60s, 0.013s, 0.013s`; `flash` (plain, non-splash) at `0.39s, 0.0078s, 0.0078s`. Reading these: (1) the first iteration of every mode is dominated by one-time JIT compilation (3+ seconds vs sub-100ms steady-state); (2) at steady state, `static` (mask baked into the trace) is roughly 2x faster than `dynamic` (mask as a traced argument) for the same full mask — the cost isn't the mask's sparsity, it's whether the compiler can specialize on it; (3) `static causal` is roughly 2x faster still than `static` full-mask, since a causal mask lets the splash kernel skip whole blocks above the diagonal; (4) the plain dense `flash` kernel is faster than even `static causal` splash in this specific shape/config, suggesting splash's sparsity bookkeeping overhead isn't recovered by block-skipping alone at this `(seq=8192, heads=16, head_dim=128)` size — sparsity has to be sparse *enough* to pay for the mechanism.

## Edge cases
- [`SplashAttention.create_mask`](../catalog/jax_perf/splash_attention_debug.md#SplashAttention.create_mask) raises `NotImplementedError` if both `dynamic_mask` and `self.window_size` are set — windowed (local) attention is a static-mask-only feature in this wrapper.
- [`SplashAttention.splash_attention_helper`](../catalog/jax_perf/splash_attention_debug.md#SplashAttention.splash_attention_helper) raises `ValueError` if exactly one of `q_segment_ids`/`kv_segment_ids` is provided — segment ids must be given as a matched pair or not at all (partially handled by `__call__`'s default-fill, but only in the `kv_segment_ids`-only case).
- [`SplashAttention.sequence_block_factor`](../catalog/jax_perf/splash_attention_debug.md#SplashAttention.sequence_block_factor) reads `self.mesh.shape["seq"]` — this hard-requires the mesh to have an axis literally named `"seq"`, even though [`_qkvo_partition_spec`](../catalog/jax_perf/splash_attention_debug.md#SplashAttention._qkvo_partition_spec) uses `_sequence_partitions` (`("seq",)` by default) as an overridable indirection; a subclass overriding `_sequence_partitions` without also overriding `sequence_block_factor` would look up the wrong mesh axis name.

## Open questions
> [!inferred] Whether the `flash` > `static causal` splash result generalizes beyond this exact shape (dense, uniform causal mask at seq=8192) or is specific to this benchmark's configuration is not something the source establishes — the file's own framing (four modes, timed back to back) suggests it was written precisely to answer "when does splash's sparsity overhead pay for itself," and the embedded numbers only answer that for one point in the configuration space.
- The `id_to_rank` field on [`CausalMask`](../catalog/jax_perf/splash_attention_debug.md#CausalMask) is set but the mask function does not reference it — dead parameter, possibly a leftover from an earlier version of the grouped-causal experiment.
