# llama_ref/model_with_collectives — manual FSDP/TP collectives + scanned layers
The `model_impl='scan_manual'` variant of the `llama_ref` Llama3 port: instead of letting GSPMD auto-partition the model from `with_sharding_constraint` hints (as [model_with_scan](llama_ref-model_with_scan.md) does), this file issues the tensor-parallel all-reduce and the per-layer FSDP weight all-gather *explicitly*, using JAX collectives wrapped for PyTorch tensors via `torch_xla2`'s interop layer, and tags rematerialization boundaries by name with `checkpoint_name` for a host-offload checkpoint policy.

## Entry points
- [`Attention.forward`](../catalog/llama_ref/model_with_collectives.md#Attention.forward) — after the `wo` output projection, calls [`all_reduce_sum`](../catalog/llama_ref/model_with_collectives.md#all_reduce_sum) `(out, axis_name='tp')` explicitly — the tensor-parallel reduction that fairscale's `RowParallelLinear` performed implicitly in [model_original](llama_ref-model_original.md), and that GSPMD inferred from a sharding hint in [model_with_scan](llama_ref-model_with_scan.md), is here a plain, visible collective call.
- [`Transformer.forward`](../catalog/llama_ref/model_with_collectives.md#Transformer.forward) — embeds tokens via [`tok_embeddings`](../catalog/llama_ref/model_with_collectives.md#Transformer.tok_embeddings), calls [`all_gather`](../catalog/llama_ref/model_with_collectives.md#all_gather) on the embedding output (tensor-parallel axis, tiled) before entering [`layers`](../catalog/llama_ref/model_with_collectives.md#Transformer.layers), then all-gathers again after [`output`](../catalog/llama_ref/model_with_collectives.md#Transformer.output) — tensor-parallel sharding of the vocab dimension is explicitly un-sharded (gathered back to replicated) at both the input and output boundary of the layer stack.
- [`ScanLayer.forward`](../catalog/llama_ref/model_with_collectives.md#ScanLayer.forward) — the per-scan-step body; unlike `model_with_scan.py`'s `ScanLayer`, this one calls [`eval_one_layer`](../catalog/llama_ref/model_with_collectives.md#ScanLayer.eval_one_layer) which itself performs a per-layer FSDP weight all-gather before invoking the shared submodule, and additionally supports [`unroll_layers`](../catalog/llama_ref/model_with_collectives.md#ScanLayer.unroll_layers) `> 1` (multiple physical layers evaluated per scan step, via a Python `for` loop inside the scanned body).

## Mechanism (step-by-step)
1. [`ScanLayer.forward`](../catalog/llama_ref/model_with_collectives.md#ScanLayer.forward) reconstructs the per-layer weight dict from [`params`](../catalog/llama_ref/model_with_collectives.md#ScanLayer.params) keyed by [`layer_weights_keys`](../catalog/llama_ref/model_with_collectives.md#ScanLayer.layer_weights_keys) (using [`_param_name_new`](../catalog/llama_ref/model_with_collectives.md#ScanLayer._param_name_new) to translate dotted state-dict keys into the flat, `___`-joined names a `ParameterDict` requires), then dispatches to [`eval_one_layer`](../catalog/llama_ref/model_with_collectives.md#ScanLayer.eval_one_layer) for the actual scan body.
2. [`eval_one_layer`](../catalog/llama_ref/model_with_collectives.md#ScanLayer.eval_one_layer) loops [`unroll_layers`](../catalog/llama_ref/model_with_collectives.md#ScanLayer.unroll_layers) times per scan step, and for each of those physical layers calls [`gather_and_call`](../catalog/llama_ref/model_with_collectives.md#ScanLayer.gather_and_call) — this is the FSDP unshard step, done fresh for every layer on every scan iteration rather than once up front, trading repeated communication for never holding more than one layer's full (unsharded) weights in memory at a time.
3. [`gather_and_call`](../catalog/llama_ref/model_with_collectives.md#ScanLayer.gather_and_call) all-gathers each weight tensor individually via the module-level [`all_gather`](../catalog/llama_ref/model_with_collectives.md#all_gather) helper, choosing the gather axis per-weight from `_fsdp_axis(k)` (visible in source but not in this packet's cited subgraph — it returns axis `1` for `wq`/`wk`/`wv`/`w1`/`w3` and axis `0` for the rest, matching which dimension of each weight matrix is FSDP-sharded), then calls the shared submodule [`m`](../catalog/llama_ref/model_with_collectives.md#ScanLayer.gather_and_call) (referenced via `calls/refs`) via `torch.func.functional_call` with the now-fully-gathered weights.
4. Inside [`Attention.forward`](../catalog/llama_ref/model_with_collectives.md#Attention.forward), the tensor-parallel dimension is handled the mirror-opposite way from FSDP: `wq`/`wk`/`wv` are constructed sized by the *global* head count (this file's `Attention.__init__`, visible in source, divides by `args.tp_size` to get local head counts — same shape logic as `model_original.py`'s fairscale layers, but expressed as plain `nn.Linear` plus a manual reduction rather than a parallel-layer class), and after `wo`, [`all_reduce_sum`](../catalog/llama_ref/model_with_collectives.md#all_reduce_sum)`(out, axis_name='tp')` sums the partial outputs from every tensor-parallel shard — functionally identical to fairscale's `RowParallelLinear`, just spelled out.
5. [`apply_rotary_emb`](../catalog/llama_ref/model_with_collectives.md#apply_rotary_emb) and [`reshape_for_broadcast`](../catalog/llama_ref/model_with_collectives.md#reshape_for_broadcast) — reached from `Attention.forward` — are unchanged from the other three `llama_ref` model files; rotary embedding math is the one piece of the attention path that never varies across the sharding-strategy experiments.

## Key data structures
- [`ScanLayer.params`](../catalog/llama_ref/model_with_collectives.md#ScanLayer.params) — an `nn.ParameterDict` holding every layer's weights *stacked* along a new leading axis (one tensor per original state-dict key, shape `(num_layers, ...)`), keyed by [`_param_name_new`](../catalog/llama_ref/model_with_collectives.md#ScanLayer._param_name_new)-mangled names; this is the FSDP-sharded representation that [`gather_and_call`](../catalog/llama_ref/model_with_collectives.md#ScanLayer.gather_and_call) unshards one layer-slice at a time.
- [`ScanLayer.layer_weights_keys`](../catalog/llama_ref/model_with_collectives.md#ScanLayer.layer_weights_keys) — the ordered list of original (dotted) parameter names, captured once from the prototype submodule's `state_dict()` at construction time, used to reconstruct the weight dict on every forward call.
- [`ScanLayer.unroll_layers`](../catalog/llama_ref/model_with_collectives.md#ScanLayer.unroll_layers) — controls how many physical transformer layers are evaluated per `jax.lax.scan` step; `> 1` trades scan-step count for larger fused HLO per step (and, since each unrolled sub-layer still calls `gather_and_call` separately, does not reduce the number of FSDP all-gathers — only the number of *scan* iterations).

## Dynamics (design intent)
> [!inferred] Because every collective in this file ([`all_gather`](../catalog/llama_ref/model_with_collectives.md#all_gather), [`all_reduce_sum`](../catalog/llama_ref/model_with_collectives.md#all_reduce_sum)) is issued explicitly rather than inferred by GSPMD, this variant exists to answer a specific question the `model_with_scan.py` hint-based variant cannot cheaply answer: whether *programmer-controlled* placement of FSDP unshard/TP reduce operations beats the compiler's own choices for a given (mesh shape, model size) pair — the `checkpoint_name` tags on `query_proj`/`key_proj`/`value_proj`/`out_proj`/`decoder_layer_input` correspond exactly to the same offload-policy names used in `model_with_scan.py`, so both variants are tested under the same rematerialization/offload budget.

## Edge cases
- [`gather_and_call`](../catalog/llama_ref/model_with_collectives.md#ScanLayer.gather_and_call) all-gathers weights fresh on *every* scan iteration (there is no cross-iteration weight cache) — this is a deliberate memory/communication tradeoff (never materialize more than one unsharded layer at a time) rather than an oversight, consistent with FSDP's standard shard-then-gather-per-use pattern.

## Open questions
> [!inferred] Whether `unroll_layers > 1` changes the FSDP communication pattern (e.g. batching multiple layers' all-gathers together) or purely affects HLO fusion granularity is not resolvable from this packet's cited subgraph — `gather_and_call` is invoked once per unrolled sub-layer in the visible source, suggesting the latter, but the full `eval_one_layer`/`gather_and_call` interaction is only partially covered here.
