Autogenerated (mlir-tblgen) doc for the three **target-independent optimization** passes. Under the reference lens: these are the pass names and rewrite patterns you see quoted in compiler logs / pass pipelines when XLA-or-StableHLO simplifies IR *before* the target-specific (TPU) lowering. Knowing these patterns explains why an op you emitted disappeared or got rewritten by the time it reaches the HLO dump.

## The three passes

- **[`-stablehlo-aggressive-simplification`](src:docs/generated/stablehlo_optimization_passes.md#-stablehlo-aggressive-simplification)** — canonicalization. Performs graph simplifications: algebraic identities (`add(X,0)->X`, `multiply(X,0i)->0i`), broadcast/reshape/transpose merging and elimination, `gather(X, cst)->slice`, `dynamic_*(->static)` when operands are constant, `while` loop-invariant lifting, and more. The pattern list is pulled from code comments (high coverage, not exhaustive).
- **[`-stablehlo-aggressive-folder`](src:docs/generated/stablehlo_optimization_passes.md#-stablehlo-aggressive-folder)** — constant folding. `-fold-op-element-limit` caps how many result elements an op may have before folding is skipped (memory-overhead guard); `-optimize-float` allows mathematically-equivalent float rewrites (e.g. `log(sqrt(x))->0.5*log(x)`) that may perturb quantization of FP values.
- **[`-stablehlo-target-independent-optimization`](src:docs/generated/stablehlo_optimization_passes.md#-stablehlo-target-independent-optimization)** — runs simplification + folding together in one pattern set; the doc says users should **prefer this** over calling the other two directly ([options](src:docs/generated/stablehlo_optimization_passes.md#options)).
